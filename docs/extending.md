# Extension guide

## Add an Office action

1. Add a bounded JSON variant to `officeActionSchema` in `shared/src/contracts.ts`.
2. Implement the public Univer Facade calls in `server/src/office/products`. Check product type, ranges, dimensions, and stable object IDs before mutating.
3. Extend the post-ACK structural read in `readAfterWrite`. Return a JSON result and a location, never a live SDK object.
4. Update the Copilot tool description and read-only classification if necessary. A new write must remain unavailable in Ask mode.
5. Add an integration test that reloads the Unit from the server, checks content, and restores an earlier version.

Keep model-generated JavaScript inside the existing isolated script bridge; never evaluate it in Node or the trusted compiler helper. SDK imports belong in the Office adapter. Commit association stays in the gateway event hook, independent of product-specific actions.

For native methods already present in the registered product profile, use `script.read`/`script.write` before adding a one-off action. Consult `office_api`, use the fixed product binding and `univerAPI.Enum`, and await asynchronous calls. Legacy JSON plans retain `saveAs`/reference arguments. Complete the shared `office_verify` gate after all write paths, including compilers. Root runtime/service access and mutations in read plans remain blocked. Compiler/inspection programs are generated by trusted SDK modules; do not route user code into their internal execution helper. New high-level generation paths belong in `office/authoring`, with product guidance in `modules/copilot/skills`. See [AI authoring](ai-authoring.md).

## Extend document authoring

Keep Modern Markdown and Traditional Typst actions separate and check the native document flavor. Reuse the official compilers rather than translating Markdown or Typst into a second application format. Only SDK-generated programs enter the private execution helper. Full replacement preflight must finish before resetting the current Unit; partial Markdown edits start with a current-native read and retain actual execution mappings. Test a second update after worker reload, preservation of unrelated manual edits, and version restore with its mapping checkpoint. Add authoring syntax to the existing flavor reference, not to application UI.

## Add an editor capability

Register browser plugins in the matching `web/src/features/editor/univer` host, using a preset where available. Add its locale, CSS, and public Facade entry independently. Add each persisted model/resource owner to `server/src/office/products/plugins.ts`; a visible button alone is not a complete integration. Keep the Base calculator and dashboard worker composition aligned as well. Update the [feature matrix](office-features.md) and verify persistence, reload, permissions, and any required service adapter.

## Add a model provider

Add its ID/config fields to shared contracts and its constructor in `server/src/modules/providers`. Add its name and defaults to the model settings feature. Keep the key separate from the persisted profile. Normalize only public text/reasoning content exposed by that provider; do not invent hidden reasoning or store reasoning signatures.

Use a model with tool calling for direct editing. The existing connection test deliberately reports tools and reasoning as untested. A provider-specific live test requires a user's key and an explicit model ID; fixture tests prove application orchestration, not third-party API compatibility.

## Replace the conversation UI

The assistant-ui adapter takes plain messages and callbacks. Application state lives in `features/copilot/state`, transport in `api/client`, and Office mutations on the server. Replacing the chat rendering library should not change the provider or SDK adapters.

## Replace persistence

Application repositories currently use Node's built-in SQLite support. Office and history use their SDK database adapters. Replace these independently, preserving Unit IDs and revision history. Do not write into an SDK-owned SQLite schema from application modules.
